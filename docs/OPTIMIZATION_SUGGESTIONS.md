# LED跑馬燈 App 優化建議

## 1. 文件目的

本文件根據目前 `main` 分支的實作，整理介面、使用體驗、功能、資料安全、效能及工程品質的改善方向。建議優先修正會造成資料遺失、操作困惑或無障礙障礙的問題，再擴充管理及分享功能。

## 2. 現況摘要

目前 App 已具備完整的跑馬燈 MVP 流程：

- 建立、編輯、複製及刪除多組跑馬燈預設。
- 即時預覽文字、顏色、字體、速度、方向及循環間距。
- 全螢幕播放、保持螢幕常亮、鎖定播放方向及點擊暫停。
- 明亮／深色介面與六組介面主題。
- 使用 SharedPreferences 在本機保存資料。
- 不要求網路、相機、麥克風或定位權限。

核心流程已經可用，但目前仍屬 Debug Preview。正式發佈前，應優先提升資料可靠性、播放器控制、無障礙支援、響應式版面及測試覆蓋率。

## 4. 介面與使用體驗建議

### 4.1 首頁與預設管理

#### 增加刪除後復原

現況：刪除前使用對話框確認，刪除後無法復原（`Screens.kt` 的首頁刪除流程）。這會中斷操作，也無法補救誤刪。

建議：

- 點擊刪除後立即移除卡片，顯示 Snackbar「已刪除『預設名稱』」及「復原」。
- Snackbar 消失後才視為操作完成；若按下復原，恢復原本位置。
- 保留確認對話框與 Snackbar 其中一種即可，建議優先採用可復原操作。

驗收標準：使用者可在 Snackbar 顯示期間還原預設，且 App 重啟後資料狀態正確。

#### 改善預設卡片操作

現況：每張卡片同時顯示播放、編輯、複製、刪除四個操作，窄螢幕或大字體下容易擁擠（`Screens.kt` 的 `PresetCard`）。

建議：

- 保留「播放」為主要按鈕。
- 將編輯設為明顯的次要操作。
- 將複製、刪除收進更多選單，降低誤觸及視覺雜訊。
- 卡片直接顯示速度、方向與畫面方向摘要，讓使用者播放前可辨識設定。
- 預設數量增加後，加入搜尋、最近使用及自訂排序。

驗收標準：字體放大至 200% 時操作不截斷、不重疊，主要播放入口仍可一眼辨識。

#### 改善空狀態與首次體驗

現況：首次啟動會建立三組範例；刪除全部內容後才顯示空狀態（`PresetStore.kt`）。

建議：

- 首次啟動增加簡短導覽，說明「建立預設、即時預覽、全螢幕播放」三個步驟。
- 範例資料加上「範例」標示，避免使用者誤認為自己的內容。
- 空狀態除了建立按鈕，也可提供「重新加入範例」。

### 4.2 編輯器

#### 修正未修改草稿判斷

現況：新增預設時 `original` 為 `null`，因此即使沒有編輯，按取消仍會顯示「放棄變更？」（`Screens.kt` 的 `hasChanges` 判斷）。

建議：建立新增草稿時同步保存初始快照，統一比較「初始草稿」與「目前草稿」。

驗收標準：剛進入新增頁直接取消時不顯示確認；修改任一欄位後取消才顯示確認。

#### 強化即時預覽

現況：預覽高度固定為 `160dp`，最大字體為 `180sp`，在大字體或系統字體放大時可能裁切（`Screens.kt` 的編輯預覽）。

建議：

- 預覽區依裝置寬度與預設方向調整比例。
- 提供橫向、直向預覽切換，不直接旋轉整個編輯頁。
- 增加預覽播放／暫停按鈕，方便觀察文字細節。
- 顯示安全區，提示文字是否可能超出可視範圍。
- 平板採左右雙欄，左側固定大型預覽、右側捲動設定。

驗收標準：最大字體與 200% 系統字體下仍可操作，預覽不遮住設定欄位。

#### 降低色彩設定門檻

現況：自訂色只能輸入 Hex，驗證接受 `#RRGGBB` 與 `#AARRGGBB`，畫面提示卻只說明六位格式，且可建立完全透明文字（`MarqueeText.kt`、`Screens.kt`）。

建議：

- 加入視覺化色盤，Hex 輸入保留為進階選項。
- 提供最近使用色、交換文字／背景色及恢復預設。
- 明確決定是否支援 Alpha；若不需要，僅接受 `#RRGGBB`。
- 即時計算文字與背景的對比值，低於 WCAG AA 時顯示警告。
- 在色票上同時顯示顏色與名稱，不讓選擇只依賴色覺。

驗收標準：不熟悉 Hex 的使用者可完成配色；無法在未警告的情況下儲存不可見文字。

#### 改善輸入與參數調整

現況：名稱及文字沒有長度限制；顯示文字可輸入多行，但播放時會把換行轉為空格。Slider 的標籤與數值語意也不完整。

建議：

- 預設名稱限制在合理長度，例如 40 字，並顯示字數。
- 顯示文字設定較寬鬆上限，例如 2,000 字；超長時提示效能影響。
- 若產品只支援單行，輸入欄位及說明應明確標示換行會轉為空格。
- Slider 除拖曳外，提供減少／增加按鈕及可直接輸入的數值。
- 顯示清楚單位，例如 `72 sp`、`160 dp/s`、`0.05 em`。
- 速度除了「慢／適中／快」，增加實際播放一圈的預估時間。
- 編輯頁加入 `imePadding()`，避免鍵盤遮住底部欄位。

驗收標準：鍵盤開啟時目前欄位及儲存操作可見；TalkBack 能讀出每個 Slider 的名稱、數值與單位。

### 4.3 播放器

#### 提供清楚且可重新叫出的控制介面

現況：提示只顯示約 2.4 秒，之後沒有持續可見的離開入口；點擊整個畫面會直接暫停（`Screens.kt` 的 `PlayerScreen`）。

建議：

- 初次播放顯示簡短控制列，包含播放／暫停、離開及鎖定控制。
- 單擊先顯示或隱藏控制列，播放／暫停改由明確按鈕控制。
- 控制列數秒後淡出，點擊可再次叫出。
- 保留系統返回鍵，且在沉浸模式下仍應容易離開。
- 提供「鎖定觸控」避免展示時誤觸；長按或特定手勢可解鎖。

驗收標準：第一次使用者不依賴系統返回手勢，也能發現暫停及離開方式。

#### 完善無障礙語意

現況：全畫面點擊區沒有 `role`、`onClickLabel` 或狀態描述；重複繪製的跑馬燈文字可能被 TalkBack 重複朗讀（`Screens.kt`、`MarqueeText.kt`）。

建議：

- 播放控制提供「正在播放，雙擊暫停」及「已暫停，雙擊繼續」狀態描述。
- 暫停狀態使用 live region，讓輔助技術主動讀出狀態變化。
- 只保留一份跑馬燈文字的可存取語意，其餘視覺副本清除語意。
- 對純展示需求提供「不朗讀跑馬燈內容」選項。
- 讓控制列支援鍵盤、Switch Access 及大型觸控目標。

驗收標準：TalkBack 不會重複朗讀同一句文字，播放與暫停狀態都有明確回饋。

#### 修正對比與完整暫停

現況：黑色半透明暫停面板未明確指定白色內容，在明亮 App 模式可能出現低對比；動態彩虹在文字位置暫停後仍持續動畫。

建議：

- 暫停面板及提示明確使用高對比的前景色，例如 `Color.White`。
- 暫停時一併停止位移與彩虹動畫。
- 增加「靜態顯示」與「降低動態效果」模式。
- 增加「保持螢幕常亮」開關及可選的自動停止時間。

驗收標準：六組 App 主題與明暗模式下，控制文字都符合可讀性要求；暫停後不再發生持續重繪動畫。

### 4.4 設定頁與視覺系統

#### 響應式版面

現況：主題選項固定兩欄，顏色欄位固定並排，部分按鈕列不會換行（`Screens.kt`）。

建議：

- Compact 寬度使用單欄，Medium 使用兩欄，Expanded 使用三欄以上。
- 使用 `FlowRow` 讓 Chip 與卡片操作依可用空間換行。
- 窄螢幕將文字色與背景色改為垂直排列。
- 在分割畫面、橫屏、折疊裝置及平板實測。

#### 主題一致性

建議：

- 顯示模式增加「跟隨系統」，取代目前只有明亮／深色的 Boolean 設計。
- 讓深色模式的 `surfaceVariant` 隨所選 Palette 變化，而非共用藍灰色。
- 定義專屬 Typography 與元件樣式，將 App Icon 的活潑 LED 視覺延伸到首頁及編輯器。
- 使用 Android 12 SplashScreen API，避免冷啟動時深淺色短暫跳變。
- 增加 Android 13+ monochrome icon，支援 themed icon。

## 5. 功能優化建議

### 5.1 預設管理

建議依使用頻率逐步加入：

1. 刪除後復原。
2. 拖曳排序與釘選常用預設。
3. 搜尋名稱及顯示文字。
4. 最近播放清單。
5. 多選、批次刪除與批次匯出。
6. 重複名稱提示，但不強制名稱唯一。

### 5.2 匯入、匯出與分享

建議：

- 將單一或多個預設匯出為有版本資訊的 JSON。
- 透過 Android Storage Access Framework 匯入／匯出，不要求廣泛儲存空間權限。
- 匯入前顯示預覽與名稱衝突處理方式。
- 支援分享純文字及預設檔案。
- 匯入時驗證 schema、欄位範圍、顏色及文字長度，避免不可信檔案造成崩潰或資源耗盡。

### 5.3 更多播放能力

可在核心品質穩定後考慮：

- 靜態置中文字模式。
- 多段訊息依序播放。
- 播放倒數及指定播放時間。
- 鏡像文字，供透過鏡面或提詞器使用。
- 自動縮放文字，使短句盡量填滿畫面。
- 快速亮度調整，離開播放器時恢復系統原值。
- OLED 省電提示，深色背景時推薦使用純黑。

## 6. 資料安全與隱私建議

### 6.1 防止損壞資料整批消失

現況：`PresetStore.kt` 解析 JSON 時，只要資料發生例外就回傳內建範例，可能讓所有使用者預設在介面上消失。

建議：

- JSON 增加 `schemaVersion`。
- 逐筆解析，單筆損壞時保留其他有效資料。
- 覆寫前先保存最近一份可讀備份。
- 發現損壞資料時顯示錯誤與復原選項，不要靜默替換。
- 中期可改用 DataStore；若未來需要排序、搜尋或較多欄位，可評估 Room。

驗收標準：一筆無效資料不會造成其他預設消失，舊版本資料可透過自動化 migration 測試升級。

### 6.2 保存未完成草稿

現況：草稿只存在 ViewModel 記憶體，程序被系統終止後可能遺失。

建議：

- 使用 `SavedStateHandle` 保存目前草稿與原始快照。
- 長時間編輯可另存暫存草稿，正式儲存後再移除。
- 恢復時明確提示「已恢復未完成內容」。

驗收標準：在開發者選項開啟「不保留活動」後，返回編輯頁仍能恢復所有欄位。

### 6.3 明確定義 Android Backup 行為

現況：Manifest 設定 `android:allowBackup="true"`，但 README 宣稱資料只儲存在本機，也沒有 backup rules。

建議二選一：

- 若訊息不得離開裝置，關閉備份或排除預設資料。
- 若要支援裝置轉移，加入 `backup_rules.xml`、`data_extraction_rules.xml`，並在隱私說明中清楚描述系統備份行為。

## 7. 工程品質建議

### 7.1 建立自動化測試基線

目前專案沒有 `src/test` 或 `src/androidTest` 測試。至少應加入：

- `PresetStore` 正常資料、損壞資料、未知 enum、舊 schema migration 測試。
- 新增、編輯、複製、刪除及取消的 ViewModel 測試。
- 新增頁未修改時取消的回歸測試。
- 草稿在狀態重建後恢復的測試。
- Compose UI 的空狀態、刪除復原、儲存驗證及播放器控制測試。
- TalkBack 語意、大字體、窄螢幕及深淺色截圖測試。

### 7.2 字串資源與國際化

現況：`strings.xml` 幾乎只有 App 名稱，大部分介面文字硬編碼於 Kotlin。

建議：

- 將所有 UI、錯誤、主題、範例名稱移至字串資源。
- 建立繁體中文基準資源及英文翻譯。
- 使用格式化字串處理預設名稱及動態訊息。
- 使用 pseudo-locales 測試長文字，並驗證 RTL 版面。

### 7.3 導航與狀態管理

現況：`MainActivity.kt` 使用 `"home"`、`"editor"`、`"player"`、`"settings"` 字串切換畫面。

建議：短期至少改為 sealed 類型，移除裸字串；功能變多時導入 Navigation Compose，建立正式 back stack、型別安全 route 及狀態恢復策略。

### 7.4 正式發佈準備

- 設定 Release signing、R8／ProGuard 及 release build 驗證。
- 建立 CI，自動執行 unit test、lint、Compose UI test 及 assemble。
- 加入 Baseline Profile，改善冷啟動與常用操作效能。
- 更新 README 的備份、資料復原、已知限制與正式版本說明。

## 8. 建議版本路線圖

### 近期修正版

目標：消除明顯錯誤與使用障礙。

- 修正新增頁未修改仍詢問放棄。
- 修正明亮模式暫停面板對比。
- 暫停時停止動態彩虹。
- 增加播放器明確的離開及播放控制。
- 為播放器及 Slider 補齊無障礙語意。
- 增加資料解析及 ViewModel 最低測試。

### 下一個功能版

目標：提升日常管理與設定效率。

- 草稿恢復及資料 schema migration。
- 刪除後復原、排序、搜尋及釘選。
- 色彩選擇器、對比警告及最近使用色。
- 響應式版面與平板雙欄編輯。
- 跟隨系統主題及降低動態效果。

### 正式發佈版

目標：達到可公開發佈與長期維護的品質。

- 匯入、匯出及分享。
- 明確的 Android Backup 與隱私策略。
- 完整字串資源、多語系與 RTL 驗證。
- CI、release signing、R8 及 Baseline Profile。
- 實機覆蓋手機、平板、橫直向、大字體及 TalkBack。

## 9. 成效指標

實作優化後，可用以下指標驗證效果：

- 建立第一個自訂預設的完成率與耗時。
- 編輯頁取消、驗證失敗及未儲存離開的發生率。
- 播放器中成功找到暫停及離開功能的比例。
- 預設誤刪後成功復原的比例。
- 損壞資料、程序死亡與版本升級測試的通過率。
- TalkBack、大字體 200%、窄螢幕及平板測試通過率。
- 播放及暫停狀態下的耗電與重組／重繪情況。

## 10. 結論

目前 App 的核心價值清楚，使用流程也足夠精簡。下一階段不應優先堆疊更多視覺主題，而應先確保預設不會遺失、草稿可恢復、播放器容易控制，並讓大字體及輔助技術使用者也能完成相同任務。完成 P0 與 P1 項目後，再加入匯入匯出及進階播放能力，能以較低風險將專案從 Debug Preview 推進至正式版本。
